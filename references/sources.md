Created 2026-11-07 by assembling existing parts, per the user direction to build from prior parts and then check the assembled whole for consistency. The user's own wording is kept for the steps the user specified: the AI interviews the user during preparation and reading starts once preparation is complete, structure is part of that hearing when needed, masking necessity is asked of the human when a long document arrives, and whether the document was read to the end must be confirmed.

## What the finished skill must let a later conversation do

Take one long PDF from arrival to a verified full read: diagnose it mechanically, hear what only the user knows, settle masking with the user on evidence, convert it safely, read it in structural units, prove the read covered everything, and hand the work to another agent such as Copilot without losing those guarantees.

## Masking decision design (user question, 2026-11-07)

The user asked whether asking the human each time a long document arrives is enough, or whether a better method exists. Three options were compared.

- Ask bare, with no preparation. Keeps authority with the human, but the human often has not read the document, which is why the reading is being delegated, so the question lands blind.
- Decide by standing rule alone, such as always mask for external agents. Cheap, but blind to the content of this document, and sensitivity varies per document.
- Ask on evidence, adopted. The agent scans locally first, counts candidate items by kind, detects an already masked document, names who will read the material, and presents a recommendation. The human decides per document at low cost, external transfer waits while the decision is open, and reading inside the approved boundary can proceed. A repeated pattern can later be proposed as a standing rule, which keeps the rule earned rather than assumed.

## Independent review (2026-11-07) and fixes applied the same day

A different agent reviewed the assembled draft against the template and the sibling skill. Four critical and eight major findings were raised, and all were fixed before the test run.

- Pipeline break (critical). The masking section ran before conversion and scanned a text that did not exist yet, so the reading copy built later from the original PDF could have carried no masking while the bridge promised a masked copy. Fixed by giving the scan a throwaway local full text of its own, and by applying masking to the finished reading copy itself, with the verification run on that copy.
- Gate versus scope (critical). The completion gate demanded reconciliation against the whole document, which a question driven read the skill itself authorizes could never pass. Fixed by making the gate scope relative to the scope declared in the interview, with out of scope material named as out of scope.
- Unit size (critical). Structural units had no size cap, so one chapter could exceed a single read. Fixed with a sub split rule at subheading or paragraph boundaries and a cap fed by the pilot cost measurement.
- Missing approval (critical). The Copilot masking route depended on an accepted sensitivity that no step collected, and the bridge send had no transfer confirmation. Fixed by recording per reader rulings and a sensitivity cap in the interview, and by confirming the first transfer to each external agent with the user.
- Scan honesty (major). Name counts were promised before any dictionary existed, on detection the skill itself calls weak. Fixed by counting only pattern countable kinds and labeling the name figure a floor with its limits stated.
- Pilot budget (major). The budget was enforced but never set. Fixed with a three minute default for the pilot, recorded in the conversion record.
- Gate measure (major). Pages and lines were mixed as the gate measure, and the per unit notes were never checked. Fixed by fixing the measure to reading copy lines with page anchors alongside, and by requiring a notes entry for every unit and sub unit.
- Hearing order (major). Numbering and term questions were asked before conversion, when the document could not yet answer them, and companion material was asked about too narrowly. Fixed by splitting the hearing, with numbering and terms confirmed at the structure map stage and companion material asked about in any form.
- Unverified commands (major). Two poppler forms were incomplete as written and the named converters had no way to run them. Fixed by completing the poppler forms, verifying all six poppler tools present locally, and moving converter entry points to references/converters.md with their verification status labeled.
- Circular bridge (major). The bridge depended on the contents of a Muse skill the receiving agents cannot read, and the reading check had drifted from last paragraph to a late passage. - Input branch (major). The skill accepted only PDFs, while the precedent case arrived as Markdown. Fixed with an entry branch for text and Markdown inputs, also stated in the skill.yaml description.
- Boundary (major). The Copilot file-work skill's description pointed nowhere for long documents, and long had no size cue. Fixed on both sides, with a reciprocal sentence added to the sibling description and a size cue added here.
- Minor findings fixed in the same pass. A duplicated ask only rule was removed. The zero hit check was scoped to user supplied sensitive originals as whole tokens, with reference list hits reported instead of failing. ## Security flow for masking (user rule, 2026-11-07, corrected the same day)

The user proposed this flow on 2026-11-07, the author checked it, and the user then issued a major correction to who may read what. The corrected rule below supersedes an earlier same day version that had the permission exactly backwards.

- When a file is found to be in a security sensitive state, stop without reading it.
- When the user decides masking is needed, the pre masking file is not read by Mochi, and once it is no longer needed it is removed at once, with direct deletion acceptable instead of routing through a trash folder.
- Who may read the original of a flagged file (user correction, 2026-11-07): Copilot may, and the user's local models may. Mochi must not, and receives only the masked copy, with no unmasked derivative and no unmasked quotation. This matches the masking order the user fixed on 2026-11-06, in which Copilot reads the original, produces the masked file, and Mochi and other agents work from the masked file.
- The user's practical note on the local models, recorded the same day: they are permitted readers, but at the speed measured on 2026-11-06 a full document read is not practical, so they are assigned slices rather than whole documents, and Copilot is the default masking worker on the flagged path.

The check found the flow sound, with refinements that keep it honest.

- Detection happens at the container level only (encryption flag, sensitivity label in metadata, source, and the user's own declaration), because any content based detection would already be reading. The absence of a flag does not prove safety, so the user's declaration stays a triage input.
- On the flagged path Mochi runs no scan, because the scan extracts the full text. The user decides from container facts plus any counts a permitted reader reports.
- Deletion covers the original and every derivative made from it (scan texts, pilot outputs), happens as soon as the masked copy passes verification, and is reported as clearing the working storage, not as guaranteed erasure from system backups. A copy of a flagged original that reached Mochi's storage is deleted unread, once the user confirms a permitted reader holds the file.

A follow-up investigation on 2026-11-10 settled why the same harness treated the two local trials so differently, and the body now opens its harness section with the sizing check that follows from it. Goose's own documentation gives the trigger as the smaller of the auto-compact threshold (default 0.8) times the model's context window and an absolute token cap (default 225,000), and gives the precedence by which the window is resolved: an explicit override, then custom provider configuration, then runtime discovery against the provider, then canonical model metadata, then a default of 128,000. In the Bonsai trial the trigger fired near 52,000 tokens, which is 0.8 times 65,536, the window the llama.cpp server was serving; a search of the machine's Goose configuration found no 65,536 written anywhere and no custom provider definition file, which rules out the configuration steps of the precedence and leaves runtime discovery, the server advertising its served window (llama.cpp exposes it as meta.n_ctx in its models response, the field other harnesses read for exactly this). The 128,000 the interface displayed was the default, shown while the discovered smaller window governed the trigger. The Qwen trial, by contrast, peaked near 87,000 tokens against a trigger above 100,000 on any reading of its window, so compaction never fired. The practical rules the body takes from this: size the read against the trigger before starting, raise the served window rather than the declared one, and never declare a limit above what the endpoint serves, because overshooting requests truncate at the real cap instead of compacting.

A fifth trial (2026-11-10 to 11, Goose with Bonsai 2 again, run deliberately under the same served window of 65,536 so the compaction trigger stayed near 52,000) tested the amended checkpoint discipline end to end. The combined retrospective of the three local trials (2026-11-11) added the worksheet form of the correspondence check to the body: the three Goose runs (a full-weight Qwen, then Bonsai twice, the second with the checkpoint discipline in place) all passed the gate with identical counts and coverage while their durations spread from about 37 minutes to about 6 hours 36 minutes, the bottleneck moving each time a layer was fixed — the human's scheduling, then compaction-driven re-derivation, then generation-speed variance and small frictions. Against that background, the correspondence check is the one quality gap that survived every wording change across five trials, so its next countermeasure is mechanical rather than verbal: a tool-assembled worksheet that forces the citing passage and the list entry into one view for the judgement.

The gate form of the correspondence check followed on 2026-11-11.
